# Silk Node — Backend

Silk Node — приложение для хранения людей и связей между ними. Пользователь ведёт собственный граф знакомств, добавляет заметки и отмечает избранных людей. Этот репозиторий содержит REST API; визуализация графа находится в отдельном фронтенд-проекте.

## Возможности

- Регистрация, вход и выход с JWT в cookies.
- Автоматическое обновление access-токена через refresh-токен.
- Создание, просмотр списка и редактирование людей.
- Заметки, избранное и карточка пользователя «Я» (`is_self`).
- Создание и редактирование связей с описанием `via`.
- Проверка принадлежности людей и связей текущему пользователю.
- Защита от повторных связей, связей человека с собой и нескольких карточек «Я» у одного пользователя.
- Миграции базы данных и автоматические тесты.

Удаление людей и связей, изменение профиля и даты людей/связей пока не реализованы.

## Стек

Python, FastAPI, Pydantic 2, SQLAlchemy 2 с асинхронными сессиями, PostgreSQL, asyncpg, Alembic, python-jose и Passlib с Argon2. Тесты используют стандартный `unittest`.

## Локальный запуск

Нужны Python 3.11 или новее и работающий PostgreSQL. Команды ниже выполняются из корня репозитория в PowerShell.

### 1. Окружение и зависимости

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install argon2-cffi
```

`argon2-cffi` нужен для используемого в коде алгоритма хеширования паролей. Сейчас этот backend не указан отдельно в `requirements.txt`, поэтому его необходимо установить второй командой.

На Linux/macOS вместо `.venv\Scripts\python.exe` используй `.venv/bin/python`.

### 2. PostgreSQL

Создай пользователя и пустую базу данных. Например, выполни в `psql` под администратором PostgreSQL:

```sql
CREATE ROLE silknode LOGIN PASSWORD 'replace-with-your-local-password';
CREATE DATABASE silknode OWNER silknode;
```

Название базы и учётные данные должны совпадать с настройками следующего шага.

### 3. Переменные окружения

```powershell
Copy-Item env.example .env
```

В `.env` укажи свои значения:

| Переменная | Назначение |
|---|---|
| `DB_HOST`, `DB_PORT` | Адрес и порт PostgreSQL |
| `DB_USER`, `DB_PASS`, `DB_NAME` | Пользователь, пароль и база |
| `JWT_ACCESS_SECRET_KEY` | Секрет подписи access-токена |
| `JWT_REFRESH_SECRET_KEY` | Отдельный секрет подписи refresh-токена |
| `JWT_ALGORITHM` | Алгоритм подписи; по умолчанию `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Срок access-токена; по умолчанию 10 минут |
| `REFRESH_TOKEN_EXPIRE_DAY` | Срок refresh-токена; по умолчанию 7 дней |

Сгенерируй два разных секрета, выполнив команду дважды:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Сохраняй настоящие пароли и секреты только в локальном `.env`. В репозитории используется `env.example` с примерами, без рабочих секретов.

### 4. Миграции

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Миграции создают таблицы пользователей, людей и связей, а также частичный уникальный индекс для карточки «Я». Если обновляешь существующую базу, в ней не должно быть нескольких `is_self=true` у одного пользователя: миграция отклонит такие данные, а не удалит их автоматически.

### 5. Сервер

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host localhost --port 8000
```

- API: <http://localhost:8000>
- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>
- OpenAPI: <http://localhost:8000/openapi.json>

`--reload` предназначен для разработки. Префикса `/api/v1` у текущих маршрутов нет.

## Авторизация и фронтенд

API использует cookies `access_token` и `refresh_token`. Регистрация сразу авторизует пользователя. При отсутствии или истечении access-токена защищённый запрос может обновить его через refresh-cookie; отдельного маршрута refresh нет.

Для браузерных запросов используется `credentials: "include"` или `withCredentials: true` в Axios. Заголовок `Authorization: Bearer ...` текущая авторизация не использует.

CORS разрешает фронтенд с адреса `http://localhost:5173`. В локальной среде используй одинаковый hostname `localhost` для фронта и API. Refresh-cookie имеет флаги `HttpOnly`, `Secure` и `SameSite=Lax`; работа по HTTP на localhost проверялась в Chromium. Для размещения на сервере нужен HTTPS и настройка CORS под фактический адрес фронтенда.

Регистрация создаёт только запись пользователя. Фронтенд создаёт карточку «Я» через обычный маршрут создания человека с `is_self: true`, если она отсутствует.

## Маршруты API

Все маршруты людей, связей и `/users/me` требуют авторизации.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/register` | Регистрация и установка cookies |
| POST | `/auth/login` | Вход и установка cookies |
| POST | `/auth/logout` | Удаление cookies |
| GET | `/users/me` | ID, email и дата регистрации текущего пользователя |
| GET | `/person` | Список людей текущего пользователя |
| POST | `/person/create` | Создание человека |
| PATCH | `/person?person_id=1` | Частичное обновление человека |
| GET | `/connections` | Список связей текущего пользователя |
| POST | `/connections/create` | Создание связи |
| PATCH | `/connections?connection_id=1` | Частичное обновление связи |

`GET /person` возвращает список; отдельного GET одного человека по ID пока нет.

### Регистрация и вход

Оба маршрута принимают:

```json
{
  "email": "demo@example.com",
  "password": "your-password"
}
```

Успешные ответы имеют статус `200`: регистрация возвращает `{"message":"user created successfully"}`, вход — `{"message":"login successful"}`.

### Создание человека

`POST /person/create` — все четыре поля обязательны:

```json
{
  "name": "Анна",
  "note": "Познакомились в университете",
  "is_self": false,
  "is_favourite": false
}
```

Ответ содержит `id` и перечисленные поля. ID из ответа нужно использовать в последующих запросах.

### Обновление человека

`PATCH /person?person_id=1`:

```json
{
  "is_favourite": true,
  "note": null
}
```

Пропущенные поля сохраняют прежние значения. `note: null` очищает заметку. Явный `null` для `name`, `is_self` и `is_favourite` отклоняется с `422`.

### Создание связи

`POST /connections/create`:

```json
{
  "person_id_a": 1,
  "person_id_b": 2,
  "via": "Университет"
}
```

Оба человека должны существовать и принадлежать текущему пользователю. API сортирует пару ID, запрещает одинаковые ID и повторную пару независимо от порядка участников.

Пример ответа:

```json
{
  "id": 1,
  "person_a_id": 1,
  "person_b_id": 2,
  "via": "Университет"
}
```

Обрати внимание на разные имена полей: при создании — `person_id_a`/`person_id_b`, в ответе и PATCH — `person_a_id`/`person_b_id`.

### Обновление связи

`PATCH /connections?connection_id=1`:

```json
{
  "via": "Работа"
}
```

Можно менять `person_a_id`, `person_b_id` и `via`. Пропущенные поля и явный `null` оставляют прежние значения. Итоговая пара снова проверяется и сортируется.

### Ошибки

Ошибки приложения возвращаются как `{"detail":"сообщение"}`. Ошибки валидации Pydantic имеют статус `422` и массив в `detail`.

| Статус | Примеры |
|---|---|
| `400` | Одинаковые ID участников, неверный пароль, email уже используется |
| `401` | Отсутствующая или недействительная авторизация |
| `404` | Человек или связь не найдены у текущего пользователя; неизвестный пользователь при входе |
| `409` | Повторная связь или вторая карточка «Я» |
| `422` | Отсутствующие обязательные поля или недопустимые значения |

Конфликты уникальности при сохранении также обрабатываются с откатом транзакции и ответом `409`.

## Структура проекта

```text
app/
  api/v1/        # Маршруты FastAPI
  core/          # Настройки, подключение к БД, зависимости
  models/        # Модели SQLAlchemy
  repositories/  # Запросы к БД
  schemas/       # Схемы Pydantic
  services/      # Проверки, авторизация и операции приложения
  main.py        # Приложение и CORS
alembic/         # Миграции
tests/           # Автоматические тесты
env.example      # Пример конфигурации
requirements.txt
```

Запрос проходит через маршрут, сервис и репозиторий. Сервис проверяет доступ и правила приложения; ограничения БД обеспечивают уникальность при конкурентных запросах.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В текущем наборе 14 тестов: PATCH и `null`, доступ к людям, единственность карточки «Я», дубликаты связей, конфликты ограничений PostgreSQL и работа сессии после отката.

Интеграционные тесты подключаются к PostgreSQL из окружения, создают отдельную случайную схему для каждого теста и откатывают её вместе с тестовыми данными. Пользователю БД нужно право создания схем. Для тестов предпочтительна отдельная база: укажи её в переменных окружения или `.env`. Конфликт после пропуска предварительной проверки моделируется намеренно; сами ошибки уникальности возникают в настоящем PostgreSQL.

Проверка соответствия моделей схеме после применения миграций:

```powershell
.\.venv\Scripts\python.exe -m alembic check
```
